The point

A graph is only useful
when it can answer why.

Most memory tools give you a list and a search box. This one gives you the shape: which memories keep appearing together, which project they belong to, and what evidence made the link.

01

Start from a word, then walk outward along real edges. Every hit carries its path, its workspace, and the reason it surfaced.

02

Evidence you can stand on

A slice you can hand over

What is inside

Small surface,
deep map.

No daemon to babysit, no account to create. A plugin inside DSH, or a standalone engine on loopback when you want the CLI.

Search / recall

Search is a seed, not a filter.

Type one word. The map returns direct hits, then the neighbours they activate, with a budget so a common word cannot flood the page.

Snapshots

One file. Zero network.

A whole graph or one slice becomes a self-contained HTML file. Open it on a plane, send it to a client; it still searches and draws evidence locally.

Boundary

Private by default. Honest about exports.

Every store opens read-only. Writes stay in $DSH_HOME/memory-nebula. The only way text leaves is the export you ask for.

Scale
20,000nodes · 2.53s

Entity pairing gets a budget above 12k nodes, candidate scoring stops allocating strings. Ten thousand stays at 1.2s; twenty thousand fits in a 3s build and 248MB heap.

Operations

A doctor that speaks first.

Nine read-only checks: Node version, package files, profile wiring, bundled version, sources, endpoint, and version drift. If a blank page is a restart problem, it says so.

CLI / CI

A CLI for the rest of us.

--share, --export, --scope, --token, --diagnose. Build a snapshot in CI, gate a release on 100 tests, or diagnose a customer without touching their memory text.

Install

Three commands
and a look.

Install from the curated catalog, open the page inside DSH, and run the doctor only if something looks empty. No build step, no database migration, no account.

dsh plugin --profile web add dsh-memory-nebula
npm install dsh-memory-nebula@latest

Prefer the CLI? npx dsh-memory-nebula starts the standalone engine on 127.0.0.1:7890.

The boundary

What it does.
What it refuses.

This is a viewer, not a sync service. The limits are part of the design, not a roadmap promise.

  • Reads only. Every adapter opens its store read-only; the plugin writes only to its own directory.
  • Loopback only. Host and Origin are pinned; a DNS-rebinding request gets 403 before it reaches memory.
  • No account system. Standalone can add an optional local token; without it, the model is one local user on one machine.
  • Exports are plaintext. A snapshot contains the text in its scope. Treat it like a backup, because that is what it is.
  • No cloud, no telemetry. There is no upload path, no analytics key, and no “sign in to continue”.
