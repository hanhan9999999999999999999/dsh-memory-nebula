# 路线图：从「能用到」到「敢卖」

这份路线图写给两个读者：想知道下一个版本值不值得等的现有用户，和评估这个产品能不能
作为商业组件交付的人。原则只有一条：**先把一个人每天真的会打开的那条路修顺，
再谈规模与国际化。**

## 已经成立的地基（0.5.0）

- 真实的建图管线：6 类边、来源节点、共激活、人工策展与屏蔽、6 类体检，不是装饰性可视化。
- 三种视图（星云 / 星系 / 时间）+ 筛选 + 时间回放 + LOD，1500+ 节点在无头软件 GL 下仍可交互。
- 检索与工具面：`nebula_recall` / `bridge` / `path` / `hygiene` / `sources` / `ingest`，
  以及给别的插件用的每轮邻域注入与注入账本。
- 可交付性：`/export`（MD/JSON）、当前视图 PNG、`/share` 单文件离线快照。
- 可运维性：host / standalone 双形态、热载、12 秒增量轮询、ETag 304、版本漂移横幅、sidecar。
- 发布质量：137 项单测、63 项冒烟、21 项安全探针、静态发布检查、91 文件 3.2MB 的 npm 包（1.7.0）。

## 1.6 「本机口令」（1.6.0 已交付）

**问题**：独立引擎默认没有账号，能打开本机端口的人就能读；目录评审也把这条写进了描述。

- `standalone --token <至少 12 字符>` / `NEBULA_TOKEN`：所有路由（页面、静态、API、分享、导出、诊断）
  都要 `nb_token` cookie、`Authorization: Bearer`，或首次 `?token=` 换 cookie；短口令拒绝启动。
- cookie 是 `HttpOnly; SameSite=Strict`，页面加载后把 `?token=` 从地址栏历史移除；
  比较用 `timingSafeEqual`。不传 token 时保持原来的本地即开即用。
- 宿主模式不读这个参数，继续走 `ctx.connection.requestRejection` 与 Host 围栏。
- 99 单测；不改变 `/share` 的明文出口语义。

## 1.7 「键盘也能游」：不用鼠标也能走完整座星图（1.7.0 已交付）

**问题**：三张画布都是 `aria-hidden`，`tabindex` 全库为 0。鼠标用户能做的事，
键盘用户一件也做不了；读屏用户打开页面只听到一句标题——这是商业采购里最容易被一条
验收清单刷掉的地方。

- 星图层 `#skykeys`：方向键按屏幕方向挑下一颗（`cost = 距离 × (1 + 1.5 × 垂直偏移 / 前进距离)`，
  `along < 2px` 跳过、打平按 id 取小），`Enter` 打开、`[` `]` 沿连接走、`+` `-` 缩放、
  `0` 回全图、`Home` 跳连接最多的那颗、`Esc` 逐层退出。
- 每次移动都用 `aria-live="polite"` 播报「当前位置：标题 · 工作区」，同一句连按也能重播。
- 读屏另有纯文本摘要（几条记忆、几条连接）与索引（按重要度前 300 条），画布保持对可访问性树隐藏。
- 2D / 3D 两个渲染器各补 `centerOn` / `zoomBy`，缩放的限位与滚轮一致；单文件快照内联 `nav.js`。
- 126 单测（+10 导航几何、+10 结构门、+1 静态资源、+1 示例来源、+1 地标与控件命名）、63 项冒烟；

## 1.8 「大响应不再整包重传」：传输契约（1.8.0 已交付）

**问题**：探针发现 `/graph` 全程没有压缩——真实库 2000+ 节点约 1MB、2 万条约 20MB，
每次打开或换库都整包重传；静态前端约 300KB 且 `no-store`，刷新一次重下一次。
同一轮审计还抓到两个交付契约的破口：`/export?scope=zzz:nope` 会静默按 `all` 导出整库，
`format=exe` 照发 markdown；超过 256KB 的请求体被 `req.destroy()` 直接切断，
客户端只看到 `fetch failed`，读不到「为什么被拒」。

- 新增 `lib/host/compress.js`：RFC 9110 协商 br / gzip / deflate（`q=0` 拒绝、`*` 通配、
  显式项优先），只压文本类且 ≥1024B；`vary: accept-encoding` 与压缩后的 `content-length` 一起发。
- `/graph` 改弱 ETag `W/"<sig>-<build>"` + `no-cache`，304 也带 `vary`；静态资源加强 ETag
  （mtime+size）+ `no-cache` + 304，压缩结果按 `name:mtime:encoding` 缓存。
  `HEAD` 与 `GET` 共用路由表，只发头不发正文。
- 示例库实测：`/graph` 24,384B → gzip 5,066B（79.2%）→ br 4,412B（81.9%）；
  `app.js` 139,815B → gzip 44,261B（68.3%）；`/share` 420,399B → br 113,285B（73.1%）。
- 超大请求体改回 413 + `connection: close`（先停读、写完再断），不再重置连接。
- `/export` 的 `format` / `scope` 收紧为白名单，手误直接 400，避免「以为导了一个工作区、实际写了整库」。
- 137 单测（+10 传输契约、+1 Vary 合并）、63 冒烟、25 安全探针，另有 `dev/verify-1.8.mjs` 16 项真机字节级复验。

## 1.9 「五万条也不糊成一片」（1.9.0 已交付）

**问题**：基准脚本把最大的那堵墙量出来了——5 万条时旧算法只连出 **280 条边**、
**49,567 条孤岛（99.1%）**（高频词整条被丢弃）；整图 JSON **22.3MB** 首屏一次吃完；
5 万节点 / 15 万边的一帧要 **477.8ms**；单文件快照 **43.8MB**。三处塌陷分别在
服务端建图、传输面、渲染循环，所以分三层修。

- **建图**（`lib/host/graph.js`）：`n > 20000` 走滑动窗口取样配对（关键词 3 / token 2 /
  实体 3），不再整条丢弃高频词；倒排表按 `importance → heat → 序号` 排序，重要记忆先入样；
  度数上限 16 → 8（16 条会产生 39 万边、50MB，收益只是看起来更密）。5 万条：
  **197,569 边 / 0 孤岛 / avgDegree 7.9**；1 万条 78,593 边、2 万条 156,993 边，
  与改动前逐条一致——取样只作用于 >2 万的图。
- **分页**（`lib/host/page.js`、`/graph?limit=&offset=`、前端「继续加载」）：稳定名次
  `importance → degree → id`，默认首屏 10,000 条。整图 22.30MB → 首屏 **4.26MB（−80.9%）**，
  br 1.84MB → **0.35MB**；两页节点重叠 **0**，跨页边 6,560 条（用真 id 发）。
  `sig` 不符回 **409** 让前端重来，拼错的 `limit` / `offset` 回 400，ETag 带页参数。
- **视口裁剪 + 边 LOD**（`lib/web/render.js`）：节点网格 96、边网格 384 世界单位；
  `pick()` 查格（2,000 次 6.5ms）；节点 ≥2 万且缩放 <1 时画簇间聚合线（同簇边合并，
  不是丢弃）。5 万 / 15 万：一帧 **477.8ms → 11.5ms**，放大后候选边占 **1.19%**。
- **快照分片**（`lib/host/share.js`）：`/share?limit=` 默认 20,000、上限 50,000，
  超出按重要度裁剪并在**页面上**写明「已写入 X / Y 条」。5 万条快照 **43.8MB → 16.6MB**。
- 163 单测（+11 分页、+8 分页 HTTP、+7 快照上限）、63 冒烟、25 安全探针；四个真机探针
  （分页数据 16、分页 UI 12、视口裁剪 11、快照分片 15）全过。
- 过程教训：基准 fixture 起初让边跨簇，长边 bbox 横穿全图，放大后候选仍 99.86%——
  **数据分布错了，指标会骗人**；改成同簇邻居才量到真实的 1.19%。

## 1.9.2「新加的东西也要能被读屏用」（1.9.2 已交付）

- 1.9.0 的分页条是纯视觉实现：状态变了读屏听不到，按钮和说明也没关联。1.9.2 补齐：
  状态文字 `role="status"` + `aria-live="polite"` + `aria-atomic`，按钮 `aria-describedby`，

## 1.11.4「长活分片，事件循环不让路」（1.11.4 已交付）

1.11.3 把 `/overview` 的体量砍到 83KB，但**算它要 2.9 秒**这件事没解决。2 万条库上

- 交付：`buildGraph` / `auditHygiene` / `scanAll` 各拆成「生成器 + 同步壳 + 异步壳」，

- 数字：`refresh` 全程 3,791ms、最长空档 **59ms**（原来整段 3.6 秒）；真机独立连接下

- 代价：异步建图比同步慢约 **10%**（600+ 次 `setImmediate` 的调度开销）。
- 教训：**尺子错了，结论就全反了**。用 `fetch` 复用连接池测「静默」，量到的是 HTTP 排队——
  745ms 的 `/recall` 报成 738ms 静默、3.8 秒的 `/refresh` 报成 4.2 秒；换成每次新连接，
  同一个 `refresh` 的静默只剩 37ms。性能结论必须能说清「你在量哪一段」。
- 还没做的：`/recall` 仍是同步（2 万条 633ms，检索走的是索引查找，实测没有按住事件循环）。

## 1.11.6「重复检测快了 3 倍，一对都没少」（1.11.6 已交付）

1.11.5 留了一笔账：5 万条的库上体检 6.5 秒，九成花在重复检测——907 万次候选迭代、
58 万对，每对都真的算 24 词 Jaccard，还要为每一对拼一个字符串键。

- 交付：两段式重复检测。①**正文一字不差分桶**（O(n)）：同一段记忆被抄进几个工作区是
  最常见的重复形态，而这类副本共享的词在库里出现几百次，只靠倒排会漏；
  ②近似重复走**稀有词倒排 + 下标数值键**，Jaccard 仍是原来那个提前退出实现。
- 数字：旧 2,966ms / 400,869 对 → 新 965ms / **400,869 对**（3.1x，漏 0 多 0）；
  体检 6.5s → 3,819ms；`/overview` 6,740ms → 4,240ms；`/share` 冷 3,546ms → 2,206ms、
  ping 最长 194ms 且**没有一次慢过 500ms**。
- 三个试过又撤掉的方案（都写在代码注释里，免得下一轮再试一遍）：
  ①按词频丢词（df > 400 不进倒排）→ 漏 13.6 万对，漏的全是「共享的只有常用词」的副本；
  ②共享词数下界预筛（`inter < need` 就不算 Jaccard）→ 倒排每条只留 60 条、`inter` 是低估，
  又漏 8.8 万对；③复用建图时的 token → 建图的 token 来自「标题+正文+项目+关键词」，
  比体检需要的正文 token 多两三倍，反而从 4.5s 涨到 6.6s。
- 教训：**「看起来无损」不算无损，和暴力实现逐对对比过才算**。这一轮的定论全部来自
  `dev/probe-dup-equivil.mjs` 那一次「漏 0 多 0」。
- 抽样上限（写在代码注释与文档里）：每词最多 60 条进倒排、每个正文桶最多取前 60 条。
  这是 O(n²) 不可行的原因，`counts.dup` 与展示同口径。
- 还没做：`/refresh` 还剩 782ms 单块（`scanAllSteps` 只在库与库之间 yield）。

- 修法：默认先比指纹；`?force=1` 才强制；回报 `rebuilt / unchanged / why / refreshMs` 三态。
- 结果：第二次 6,901ms → 146ms；界面从「已重建」改成照实说。
- 教训：**被默认参数关掉的捷径不会报错，只会慢**——而慢得看起来天经地义。

## 1.11.23「一秒钟的 toast，不该是唯一的告示」（1.11.23 已交付）

## 1.11.19「读一个库的那 110ms 里，事件循环一次都没让」（1.11.19 已交付）

`scanAllSteps` 只在库与库之间让路，单个 12,500 行的库用 `.all()` 一口气拉完，约 110ms 不动。
三处适配器（meow / sqlite / ingest）改成 `scanSteps` 生成器 + `iterate()` + 每 512 行 `yield 'rows'`，
同步壳 `scan` 保留给老调用方。扫描 532ms / 空档 532ms → **450ms / 23ms**；真机 `/refresh` 7.0s → **6.3–6.6s**。

两条教训：同步段测空档要先让事件循环转一次再停表（否则 max 假报 0）；Windows 上测试 fixture 必须包事务（1500 行不包事务要挂住）。
未修：`/refresh` 的 ping max 179–186ms 来自 27.4MB 响应体的 `publicGraph + JSON.stringify`。
## 1.11.18「两个节点之间那一对字符串，换成了两个数字」（1.11.18 已交付）

- 建图的候选对键 `a + ':' + b` → `a * PAIR_BASE + b`（`PAIR_BASE = 1 << 20`），解码用
  `pairA` / `pairB` 两个取整函数，不再 `indexOf` + `slice` + `Number`。
- 建图中位 6,399 → 5,765ms；真机 `/refresh` 7,341–7,558 → 6,950–7,109ms；三个指纹逐位不变。
- 教训一：**两处拼、两处解**的协议必须一次改全——只改一处，5 项单测立刻红（`key.indexOf is not a function`）。
- 教训二：**探针自己留下的服务会污染测量**，收工要收服务（`.tmp-50k` 上那个端口 62820 的进程）。
