# 路线图：从「能用到」到「敢卖」

这份路线图写给两个读者：想知道下一个版本值不值得等的现有用户，和评估这个产品能不能
作为商业组件交付的人。原则只有一条：**先把一个人每天真的会打开的那条路修顺，
再谈规模与国际化。**

## 已经成立的地基（0.5.0）

- 真实的建图管线：6 类边、来源节点、共激活、人工策展与屏蔽、6 类体检，不是装饰性可视化。
- 三种视图（星云 / 星系 / 时间）+ 筛选 + 时间回放 + LOD，1500+ 节点在无头软件 GL 下仍可交互。
- 检索与工具面：`nebula_recall` / `bridge` / `path` / `hygiene` / `sources` / `ingest`，
  以及给别的插件用的每轮邻域注入与注入账本。
- 可交付性：`/export`（MD/JSON）、当前视图 PNG、`/share` 单文件离线快照。
- 可运维性：host / standalone 双形态、热载、12 秒增量轮询、ETag 304、版本漂移横幅、sidecar。
- 发布质量：59 项单测、53 项冒烟、21 项安全探针、静态发布检查、55 文件 1.8MB 的 npm 包。

## 1.1 「装得上」（已交付）

1.0 解决「跑起来后怎么支持」，1.1 解决「还没跑起来怎么排查」：
`memory-nebula-doctor` 只读检查 Node 下界、包文件、profile 依赖与 bundles、
已安装版本、patch 文件与可选端口，`--json` 给自动化。8 项单测，真实 profile 9 项全过。

## 0.6 「切片」：分享一个项目，而不是整座库（已交付）

**问题**：`/share` 现在导出整张图。真实用户的图里混着日记、私事、别的项目；
要发给同事或客户，只能整份发，这在商业场景里不可接受。

- `/share?scope=ws:<workspace>`、`?scope=project:<project>`、`?focus=<id>&hops=<n>`。
- UI 的导出菜单分三档：「整张星图」「当前工作区」「以选中节点为中心 2 跳」。
- 快照里保留一个 `scope` 标签（「星港产品 · 12 条 · 2026-11-10」），避免收件人误以为是全库。
- 隐私选项：`hide=diary`（按层级/工作区排除），只影响导出，不改库。（0.6 未做，挪到 0.7）
- 验收：切片后的节点、边、正文、检索、证据链全部自洽；被排除的邻居不会以空节点出现。
- 交付记录：0.6.0 已实现 ws / project / focus 三种范围与三档导出，59 项单测与实机下载验证通过。

## 0.7 「第一次就懂」：把引导做成可跳过的三步（含导出隐私选项）· 已交付

**问题**：空态解决了「没有数据」，但没有解决「有 1800 条，我该看哪」。

- 首次进入真实库时给一张可关闭的卡片：先搜一个你记得的词 → 点开一条看证据 →
  按 `Shift` 点另一条看它们怎么连上。三步都能一键跳过。
- 搜索结果为空时给「换成工作区筛选」「看看示例里类似的结构」两个出口。
- 详情里的「以它为种子扩散」加一句人话解释（不是术语）。
- 引导状态只写 `localStorage`，不碰记忆库。
- 交付记录：0.7.0 已实现三步卡片、跳过/重看、`hide=` 白名单与快照脱敏；65 项单测、56 项冒烟通过。
  0.7.1 已补齐搜索空态的三个出口、详情里「以它为种子扩散」的人话解释，并修掉进示例时旧引导卡片残留。

## 0.8 「一万条也不卡」：把性能写成预算 —— 已交付（0.8.0）

**问题**：当前验收在 1800 条；商业客户的库可能 5–10 倍。

- 随包基准 `scripts/bench.mjs`：10,000 节点 / 78,593 边，确定性合成，跑建图、检索、
  体检、证据链、快照与内存；`npm run bench`。
- 目标与实测：建图 1.3s（<3s）、首屏 0.67s（<1.5s）、检索 4.4ms（<80ms）、
  体检 0.73s、`/share` 75ms / 11.6MB（<2s）、JS 堆 131MB（<300MB）。
- 关键改动：超过 3,000 节点跳过生长动画与 420 轮力导向；1,000–3,000 节点降到 180 轮；
  大图关键词候选改用稀有词签名；分词器单次字符扫描；检索缓存 token/邻接表；
  体检只分词一次；完整说明见 `docs/benchmarks.md`。
- 边界：3D 视图不在 10k 基准内，超过 3,000 条默认停在 2D；5 万条仍需分页/裁剪。
- 每次优化都用同一基准复测，禁止「感觉快了」。

## 0.9 「说英文」：界面国际化（已交付，0.9.0）

**问题**：`README.en.md` 是英文入口，界面却只有中文；海外用户第一屏就退出。

- 已落地：不抽 key，直接把中文当源文；`lib/web/i18n.js` 400+ 条 `EN` 字典，
  代码里 419 处中文字面量用 `T('…')` 包住，静态 HTML 用 `data-zh*` 声明。
- 语言优先级 `?lang=` → localStorage → `navigator.language`；顶栏 `EN / 中` 切换并记住。
- 单文件快照内联同一份字典，`/share?lang=en` 直接打开英文；日期用 `toLocaleString`。
- 英文排版单独调过：统计条、来源计数、快捷键面板、820 宽窄屏不重叠。
- 验收：英文的空态 / 示例 / 快照 / 窄屏截图各一张，中文侧回归通过；425 键、missing 0。
- 边界：服务端错误与日志仍是中文（面向开发者的诊断信息），界面侧的错误标题与按钮已英文。

## 1.0 「敢卖」：发行与支持（1.0.0 已交付）

- **分发**：npm 公开包 + DSH 插件市场条目；提供 `.tgz`、校验和、安装/卸载/回滚三行命令。
- **可诊断**：一键「复制诊断」（版本、构建、模式、能力、最近错误、来源统计），不含正文；
  用户贴给支持即可定位版本漂移。
- **兼容矩阵**：DSH 版本、Node 22/24、Windows/macOS/Linux、Edge/Chrome、WebGL2 有无。
- **许可与品牌**：MIT 核心 + 商业支持/定制适配器作为服务，不在代码里塞授权锁；
  客户数据永远只读、可导出、可删除。
- **发布节奏**：minor 功能、patch 修复；每次发布附 `docs/verified.md` 的实测数字，
  不写「应该可以」。
- **已落地**：`GET /diagnostics`、`standalone --diagnose`、页面「复制诊断」；
  `docs/compatibility.md` 与 `docs/distribution.md`；1.0.0 包 64 文件、76 单测、63 冒烟。
- **执行记录**：维护者授权后已完成 npm 公开发布（当前 latest 1.4.0）与 GitHub Release；
  精选目录 PR 已提交（awesome-dsh-plugin#14065），等仓库满 24 小时后过年龄门。

## 1.1 「装得上」：安装体检与上架（1.1.0–1.1.7 已交付）

**问题**：1.0 解决了「跑起来后怎么支持」，但「还没跑起来怎么排查」仍然靠猜；
插件装进 profile 后，依赖、bundles、Node 版本、端口四件事任何一个不对，页面都只是打不开。

- `doctor`：只读检查 Node 下界、包文件、profile 的 dependency/bundles/installed、
  记忆源数量、可选 endpoint；warn 不阻断、fail 退出 1；JSON 与中英文两种输出。
- 版本漂移：installed 与 running 不一致时给出 warn，并明确「重启 DSH，刷新页面不够」。
- CI 增加 Package install job：打包后真的装一遍，比对版本并跑 doctor。
- 示例模式彻底不碰共享 sqlite：修掉并行 CI 下 `/share?demo=1` 的 `database is locked`。
- 上架：npm 包、GitHub 仓库/CI/Release、unpkg 市场索引、双语详情与图标；
  精选目录 PR #14065 已提交，等仓库年龄门。
- 1.1 线最终 1.1.8（Host 围栏；92 单测 / 63 冒烟 / 25 安全探针）。

## 1.2 「大到能用」：大库模式（2 万条已交付）

**问题**：10k 已经过了首屏与建图预算，但 50k 的压力探测暴露出两件事：
合成词表下关键词边会被 df 上限全部滤掉，且 RSS 到 2GB；真要大库，不能只靠调参。

- 2 万条已回到预算：实体配对上限 120→60（仅 >12k），关键词候选不存字符串数组；
  建图 **2.53s**、**156,993 边**、0 孤立、heap **248MB**；快照首屏 **947ms**。
- 10k 保持 1.23s / 78,593 边；3D 仍限 3,000 条以内。
- df 上限随规模调整的原型试过：5 万条能连起来，但建图 6.7s、RSS 2.2GB，已回退；
  5 万条仍是 280 边 / 49,567 孤立，**不支持**。
- 下一步留给 1.5：`/graph` 分页或按视口裁剪、快照按范围分片、50k 真实词表基准与
  失败降级（先出 2D 摘要，再按需加载）；验收前不把 5 万条写进支持矩阵。

## 1.3 「装得小」：快照按列存（1.3.0 已交付）

**问题**：20k 快照 23.1MB，每个节点都把字段名重复写一遍；首屏解析与传输都被拖住。

- 节点与边改为「列名写一次、下面只存值」：`nodeColumns` + rows、固定五列
  `EDGE_COLUMNS=s,d,w,t,curated`；客户端只在看到列定义时展开，旧对象格式原样兼容。
- 20k 快照 **19,996,814B**（少约 13.5%），生成 174ms；新 profile 首屏 **762ms**、
  热 profile **572ms**；建图 2.68s / 156,993 边 / heap 240MB。
- 列顺序与旧快照兼容都有单测；这是纯格式优化，不改任何语义。

## 1.4 「带得走」：命令行快照（1.4.0 已交付）

**问题**：分享仍要打开页面点导出；CI、每日归档、没有 DSH 的机器都带不走一张图。

- `node lib/standalone.mjs --share <file>`：建一次图、写自包含 HTML、退出，不起端口。
- 同一套 `scope` / `hops` / `hide` / `demo` 参数；与 HTTP `/share` 共用 `buildShareHtml`，
  不新开导出路径。
- 打包时抓到 `package.json` 把自己列成依赖，删掉并加测试锁住「运行时依赖为空」。
- 77 文件 / 2,461,678B；95 单测 / 63 冒烟；npm latest 1.4.0，Release v1.4.0。

## 1.5 待定：5 万条与目录合并后的真实验证

不先承诺版本号。两件已知的事：

- 5 万条要做分页 / 视口裁剪 / 快照分片，先出可用的 2D 摘要，再按需加载；
  在真实词表基准过关前不写进支持矩阵。
- 精选目录 PR 合并后，用 dshmarket 真机搜索、安装、升级一次；本地 fixture 只证明了
  目录读取与安装目标生成，不等于商店端到端。

## 不做的事

- 不做云端同步：这是本机记忆的查看器，上传即改变威胁模型。
- 不做自动改写记忆：星图只读别人的库，写入只发生在自己的目录。
- 不做「AI 自动总结你的全部人生」：检索与证据链已经够用，总结交给会话里的模型。
